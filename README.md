# QuizArena

QuizArena - веб-платформа для создания, прохождения и совместного прохождения учебных квизов. Проект объединяет классический Spring Boot backend, серверный веб-интерфейс на Thymeleaf и отдельный LLM-сервис для генерации вопросов по теме или загруженному материалу.

Платформа рассчитана на учебные сценарии: преподаватель или студент может быстро собрать квиз, настроить параметры прохождения, поделиться им с другими пользователями и посмотреть результаты в личном или общем рейтинге.

## Что умеет проект

- Создание квизов вручную или с помощью ИИ.
- Генерация вопросов по текстовому промпту и учебным материалам.
- Поддержка публичных и приватных квизов.
- Редактирование параметров квиза после создания.
- Копирование чужого квиза в личную коллекцию для дальнейшей настройки.
- Одиночное прохождение квиза с таймером на вопрос.
- Совместное прохождение в мультиплеерной сессии по ссылке-приглашению.
- Общие и сессионные лидерборды.
- История прохождений пользователя.
- Профиль пользователя с изменением логина и пароля.
- Метрики приложения и технический мониторинг.

## Типы вопросов

QuizArena поддерживает несколько форматов вопросов:

- **Один выбор** - один правильный вариант ответа.
- **Множественный выбор** - правильным считается только полный набор верных вариантов без лишних неверных.
- **100 к 1** - формат с несколькими популярными ответами и начислением очков по весу выбранного варианта.

В мультиплеере также используется механика **"Кот в мешке"**: игрок делает ставку перед раскрытием вопроса, а итоговые очки сессии учитывают выигрыш или потерю ставки.

## Основные пользовательские сценарии

### Создание квиза

Пользователь задает название, тему, количество вопросов, время на ответ, видимость квиза, тип набора вопросов и тип ответов. При необходимости можно добавить учебный материал, который будет использован при генерации вопросов.

Для ИИ-генерации запрос проходит предварительную проверку:

- безопасность темы;
- пригодность запроса для генерации корректного учебного квиза;
- проверка структуры ответа модели;
- дедупликация и валидация полученных вопросов.

### Прохождение квиза

При старте создается попытка прохождения. Для каждой попытки фиксируются выбранные вопросы, ответы пользователя, точность, время, итоговые баллы и место в лидерборде.

На странице результатов показываются:

- место пользователя;
- процент игроков, которых он обошел;
- количество полностью правильных ответов;
- общее количество вопросов;
- время прохождения;
- точность;
- общий лидерборд квиза.

### Совместный режим

Пользователь создает мультиплеерную сессию и получает ссылку-приглашение. Другие участники присоединяются по ссылке после авторизации. Когда сессия запущена, участники проходят один и тот же квиз.

Для совместного режима отдельно отображаются:

- результаты текущей сессии;
- общий топ по квизу;
- live-рейтинг во время механики "Кот в мешке";
- итоговые очки с учетом ставок в сессии.

Общий топ квиза при этом считается без учета "Кота в мешке", чтобы сравнение между всеми прохождениями оставалось честным.

## Архитектура

Проект состоит из нескольких связанных частей.

### Spring Boot приложение

Основное приложение находится в `src/main/java/org/example`.

Ключевые слои:

- `controller` - MVC-страницы и REST API.
- `service` - бизнес-логика квизов, попыток, мультиплеера, профиля, лидербордов и генерации.
- `repository` - доступ к данным через Spring Data JPA.
- `model` - JPA-сущности.
- `dto` - объекты запросов и ответов.
- `config` и `security` - конфигурация MVC, авторизации, CORS и безопасности.
- `metrics` - бизнес- и технические метрики.

Серверные страницы лежат в `src/main/resources/templates`, общие стили и JS - в `src/main/resources/static`.

### LLM-сервис

Отдельный Python/FastAPI сервис находится в `LLM_service`.

Он отвечает за:

- постановку задач генерации в очередь;
- обращение к LLM;
- проверку темы и запроса;
- генерацию вопросов;
- разбор ответа модели;
- хранение состояния задач генерации;
- обработку загруженных материалов.

Spring Boot приложение общается с LLM-сервисом через HTTP-клиент.

### Хранилища и инфраструктура

В проекте используются:

- **PostgreSQL** - основное хранилище пользователей, квизов, вопросов, попыток и сессий.
- **Redis** - кэширование лидербордов и быстрый доступ к рейтинговым данным.
- **Kafka** - очередь задач генерации вопросов.
- **Prometheus** - сбор метрик.
- **Grafana** - дашборды технического и бизнес-мониторинга.

## Основные доменные сущности

- **User** - пользователь платформы.
- **Quiz** - квиз с настройками, владельцем, видимостью, типом и материалами.
- **Question** - вопрос квиза.
- **AnswerOption** - вариант ответа.
- **UserQuizAttempt** - попытка прохождения квиза.
- **UserAnswer** - ответ пользователя на конкретный вопрос.
- **AttemptQuestion** - набор вопросов, закрепленный за конкретной попыткой.
- **MultiplayerSession** - совместная сессия прохождения.
- **GenerationSet** - состояние и результаты генерации вопросов.

## Лидерборды и результаты

В QuizArena есть два разных контекста результатов:

- **Общий лидерборд квиза** - общий рейтинг всех пользователей по лучшим прохождениям квиза.
- **Сессионный лидерборд** - рейтинг участников конкретной мультиплеерной сессии.

Для общего лидерборда используется базовый результат прохождения. Для совместного режима могут отображаться отдельные очки с учетом сессионных механик, например ставки в "Коте в мешке".

В вопросах с множественным выбором "правильный ответ" засчитывается только при полном совпадении выбранного набора с набором правильных вариантов.

## Безопасность и авторизация

Авторизация построена на JWT. Токен хранится в HTTP cookie `authToken`, а клиентские страницы дополнительно используют данные пользователя для удобства интерфейса.

Защищенные страницы и API проверяются interceptor'ом. Если пользователь открывает приватный маршрут без валидной авторизации, он перенаправляется на страницу входа. Для ссылок-приглашений в мультиплеер сохраняется целевой адрес, чтобы после входа пользователь вернулся к присоединению к сессии.

## Генерация вопросов

Генерация устроена асинхронно:

1. Пользователь создает квиз и задает параметры.
2. Backend формирует задачу генерации.
3. Kafka передает задачу воркеру генерации.
4. LLM-сервис генерирует вопросы и возвращает структурированный результат.
5. Backend валидирует, сохраняет и связывает вопросы с квизом.

Такой подход позволяет не блокировать пользовательский интерфейс на время генерации и показывать статус готовности квиза.

## Мониторинг

Приложение публикует метрики через Spring Boot Actuator и Micrometer. В репозитории есть конфигурация Prometheus и Grafana, включая дашборды для технических и бизнес-показателей.

Примеры отслеживаемых областей:

- состояние приложения;
- метрики HTTP-запросов;
- попытки прохождения;
- генерация вопросов;
- ошибки и задержки внешних сервисов.
